# WALL-OSS-CRP 工作区迁移（2026-11-02）

目标：此前的 Ubuntu 24.04 x86_64 / RTX 5070 Ti 主机。此包是开发工作区恢复包，保留当前代码、Git 仓库及工作树、文档、日志、两个 Python 环境、全部工作区缓存、350 条目标轨迹和外置 wheelhouse。按用户要求，**不重复迁移模型权重**，恢复后连接目标机已有模型目录。原机工作区保留。

## 在目标机恢复

1. 插入 My Passport，在文件管理器中打开 `WALL-OSS-CRP-workspace-20261102` 文件夹，右键选择“在终端打开”。
2. 目标 Ubuntu 的本地 Linux 分区需要至少 **22 GiB 可用空间**；建议预留 25 GiB。需要系统已有 `python3`、`git`、`tar`、`gzip`。无需联网或安装 Conda。
3. 执行：

```bash
bash restore.sh "$HOME/workspaces/WALL-OSS-CRP"
```

脚本优先查找此前已验证的模型目录：
`~/yuhang_workspace/wall_oss_rlt/runs/official-wall5070-20261031T063658Z-n0xT6K/models`。
若已移动模型，可显式指定包含 `wall-oss-0.5/` 和 `Qwen2.5-VL-3B-Instruct/` 的目录：

```bash
bash restore.sh "$HOME/workspaces/WALL-OSS-CRP" --models-root /已有路径/models
```

已有模型只检查清单中的 24 个文件及其大小，并建立 `models` 软链接，不复制、不改写权重，也不重新计算大权重文件的 SHA256。

请使用尚不存在的目录。脚本先完整校验 SHA256，再解压、修复环境路径和 Git 工作树、核对所有安装包版本、运行 CPU 导入与矩阵运算、源码锁和训练配置检查，最后对 1,057 个数据文件逐个核对 SHA256 并读取真实双相机帧。出现 `RESTORED_CPU_CHECKED` 即完成恢复。

脚本拒绝覆盖已有目录。此前 `/home/crp-5070ti-01/yuhang_workspace/wall_oss_rlt` 下的推理部署继续保留。不要以 `sudo` 执行恢复脚本，也不要直接解压到 exFAT 硬盘上运行。

如只校验传输包：

```bash
bash restore.sh --verify-only
```

若恢复中断，日志与 `MIGRATION_INCOMPLETE.json` 保留在目标目录；排查后换一个新目录重试。恢复后的环境已绑定目标路径；以后换路径应重新从此包恢复。

## 继续开发

```bash
cd "$HOME/workspaces/WALL-OSS-CRP"
source scripts/activate-rlt.sh
python scripts/check_wall_rlt.py --output-dir logs/migration-cpu-check
```

基础开发环境使用 `source scripts/activate.sh`；RLT 开发与 CPU 检查使用 `source scripts/activate-rlt.sh`。源码锁、训练参数和数据语义保留；恢复时仅调整运行所需的路径。原激活脚本保存在 `migration/original-activate.sh`，调整清单在 `migration/relocation.json`。

训练数据入口为 `data/top_error`，通过内部相对软链接指向原工作区缓存中的完整数据，因此不依赖硬盘原来的 `/media/pangk/...` 挂载路径。`wheelhouse` 恢复为本地实体目录。`env` 的 setuptools/packaging 以实际已安装的 pip 版本打包，保留原环境版本。

## RTX 5070 Ti 的 GPU 环境

本包的本地 Python 环境来自 RTX 3060 Ti 开发机，PyTorch 为 `2.10.0+cu130`，现有原生扩展没有在 5070 Ti 上复验。本次复制和 CPU 检查不表示 GPU 兼容验收通过。

5070 Ti 继续使用此前已经验证的 `sm_120` Docker 镜像与部署目录。此包不导入镜像、不更新驱动、不改变现有容器部署，也不启动训练或机械臂程序。恢复后查看：

- `PROJECT_STATUS.md`
- `WALL_RLT_5070Ti_Official_WALL_Runbook.md`（2026-10-31 最新说明）
- `WALL_RLT_Inference_Deployment.md`
- `metadata/rlt-5070ti-validation-20261031.json`

如果目标机已验证的镜像仍在，无需重建。若它已被删除，同一硬盘上保留的 `WALL-OSS-CRP-transfer-20261029` 和 `WALL-RLT-inference5070-20261029-v1` 可按上述文档用于离线恢复；该流程需要额外磁盘空间，不包含在本包的 22 GiB 工作区恢复预算中。

- `workspace.tar.gz`：工作区（排除 `models`，`env` 单独归档；包含隐藏文件、Git 和 `.venv-rlt`）。

Ubuntu 版本相同是环境迁移的前提之一；显卡原生扩展仍按目标 GPU 验证。[Conda-Pack 官方恢复说明](https://conda.github.io/conda-pack/)介绍了环境重定位方式。
