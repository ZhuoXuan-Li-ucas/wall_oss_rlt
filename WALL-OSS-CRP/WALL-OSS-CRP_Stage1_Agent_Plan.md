**2.1 SO101 主从映射：试采前置项**

SO101 只承担遥操作主端，抓取和实际状态反馈来自 ROKAE AR5 机械臂及夹爪。不能直接套用 SO101 leader→SO101 follower 的同构关节复制逻辑。

1. 核对 SO101 设备标识、校准文件、零位、通道顺序、正方向和读数单位。标准 SO101 为 5 个臂部运动轴加 1 个夹爪通道，不等于可独立指定任意六自由度末端位姿；现场改装以实物为准。
2. 从 AR5 驱动/文档确认关节数 n、关节顺序、控制模式、反馈字段和频率。核实夹爪支持连续开度还是二值开合、是否有实测反馈。AR5 型号已确定；控制器版本与 SDK 能力未知时列待核实项，不猜测函数、寄存器或实时接口。
3. 已有映射优先复用并验证；否则根据可靠运动学模型和控制接口实现适配。末端映射需要主端正运动学、坐标/尺度变换、AR5 逆运动学或笛卡尔接口；关节映射需要逐轴定义，不能直接复制数组。首个任务允许约束部分姿态，但须明确可控方向、固定方向、姿态补全及冗余关节处理。
4. 定义使能/暂停、初始对齐、重新接管的参考位姿和偏置，避免接管时目标跳变。夹爪单独定义开合方向、范围、死区及连续/二值映射。
5. 先离线检查单位、方向、目标连续性、不可达目标及失联处理，再由现场人员验证低速运动、夹爪开合、暂停/恢复和断连处置。限位、速度和超时保护沿用现场配置，保存映射版本及验证记录。

分别保留主端输入、映射后候选目标、最终发送目标及其时间戳/状态。控制器不提供接受确认时，标注“已发送、接受状态未知”，不得称为已执行成功。SO101 原始输入用于追溯，默认不作为策略的 action 或 observation.state。

**4. 先确定 action 的物理含义**

撤销旧的“末端 6 维＋灵巧手 6 维＝12 维”定义，按 AR5 实际控制接口选择并冻结：

| 候选 | action 组成 | 使用条件 |
|---|---|---|
| 末端控制 | 绝对位置 3＋旋转向量 3＋夹爪目标 1，共 7 维 | 可可靠记录最终末端目标，且夹爪为单控制通道；明确主端不能独立控制的姿态如何约束 |
| 关节控制 | AR5 关节目标 n＋夹爪目标 1，共 n+1 维 | 可可靠记录实际关节目标；n 由 AR5 控制器型号决定，与 SO101 通道数无关 |

7 维仅是上述末端表示和单通道夹爪下的候选。改用 rotation-6D 时为 3＋6＋1＝10 维；改用增量控制时也须同步修改数据和部署语义，不能仅改维度配置。

- 末端位置相对于哪个基坐标系、描述法兰还是 TCP，必须明确；派生训练数据建议统一米和弧度，同时保留原始值及转换方法。
- 明确轴角是旋转向量还是其他参数化；保留可获得的四元数/旋转矩阵与约定，以便后续转换到 rotation-6D。
- 夹爪明确采用连续目标开度还是二值开/关。归一化记录物理范围和 0/1 方向；未经核实，不将驱动整数值称为米、角度或实测开度。
- 训练 action 使用 ROKAE AR5＋夹爪最终下发且有效的目标。主端输入、限幅前目标、被拒绝/未发送命令不得无说明地作为专家动作；接受状态不可见时保留这一限制。
- state 使用 ROKAE AR5＋夹爪实际反馈，维度依可测信息确定，不要求与 action 相同。若夹爪反馈缺失，明确标注；后续若需增加“上一夹爪命令”特征，须单独命名，不称为测量值。
- 原始记录和导出样本保留真实维度；26 维 padding 及模型侧变换留给后续数据适配，不向原始记录塞入无意义占位维度。

若只可靠提供关节目标，保存 AR5 关节命令、真实反馈、SO101 原始输入和可获取的末端信息，标记末端 action 尚未验证。从最终关节目标经正运动学计算出的末端目标须注明派生来源。坐标、单位、主从映射或 action 来源不明时先修正，不进行大规模扩采。

**5. 同步、采样率与有效性检查**

分别记录相机采样率、数据时间网格、AR5 SDK 更新率和服务器模型请求率。数据时间网格先试 30 Hz，若不稳定可测量后改为 20 Hz 等可维持频率；数据中的动作间隔与部署动作解释必须一致，但模型请求率可因 chunk 执行而不同。网络和模型频率由端到端测试确定，不预设与相机相同。不要为凑频率静默复制图像、伪造反馈或重复增量命令。

保留各路原始采样频率。每帧图像、每次反馈和每次命令记录主机单调时钟；设备提供采样/曝光时间时也保留。设备时钟不同须说明映射和误差；不能直接比较两个设备的原始计时值，也不能把主机接收时间等同于曝光时间。

派生规则写入 data_schema.md：

1. 在统一时间网格 t 上构造观测和动作。在线可得观测使用 t 时已可获得的最近有效图像/反馈，记录它们的 age；不得使用未来帧作为当前输入。
2. 明确 action[t] 是 t 附近的哪条命令、对应哪个控制区间。保持最新绝对目标可使用定义清楚的零阶保持；增量命令不能靠重复填充处理。
3. 对丢帧、过旧反馈、拒绝命令或长间隔保留标记，必要时剔除片段/episode。不要通过无记录插值消除异常。
4. AR5 关节与夹爪的物理响应延迟是反馈的一部分，不要通过平移实际状态去掩盖滞后。分别记录主端读取、映射、下发和执行反馈时间，区分主从链路延迟与设备响应延迟。
5. 记录器与控制循环解耦：限制队列和缓冲，报告溢出；不能让磁盘写入、视频压缩或逐帧打印阻塞遥操作。

试采建议质量门槛（工程起点，须结合时间戳可信度报告）：

- episode 内时间戳单调、字段维度固定、有效数值无 NaN/Inf，图像能完整解码；
- 报告各流有效频率、丢帧/重复帧、最大间隔及对齐 age 的 p50/p95/max；
- 以导出周期 Δt=1/f 为参考，观测 age 超过一周期的样本先标记无效；接触、夹爪闭合、抬升等关键片段不得存在未处理的连续缺测；
- 若此规则使大量样本无效，先修复时钟/吞吐或调整导出频率；更改阈值必须记录理由，不能只为通过验收；
- 至少逐条人工检查全部 5～10 条试采的双路视频和目标/反馈曲线，确认动作次序、夹爪闭合、抬升及成功标签对应。

这些检查只能说明记录与对齐质量；仅有接收时间戳时，不能声称获得了硬件级同步精度。

**6. 首批采集任务与数据划分**

先用方案中的蓝色套筒或现场同等容易操作的单一物体。固定机位、工具安装、主端校准、主从映射、控制参数和起始姿态，在可操作工作区内变化物体位置，并记录摆放条件；试采稳定后再适量变化朝向。

每条示范：开始记录 → 从起始姿态接近 → 抓取 → 抬起约 10 cm → 保持约 2 秒 → 标记结束与结果。复位在 episode 外完成，或单独标记；高度与保持结果应来自实际记录/人工检查，不能用发出指令替代成功判定。

先采 5～10 条并完成导出质检，合格试采可计入后续 50～100 条成功示范总数。保留失败、滑落、重抓和质量不合格的原始记录及标签；训练候选集先纳入质量合格的成功示范，恢复示范单独标记，不将中途失败片段误删成动作不连续的成功轨迹。

按 episode 整体划分 train/dev/test，保存固定清单与 seed。可从约 70%/15%/15% 起步，并按总条数明确实际数量；同一原始轨迹的不同导出版本不得跨集合。单物体数据只能用于后续验证该任务，不支持“未见物体泛化”结论。更大规模采集等待策略闭环验证后再决定。

**7. 无大模型 GPU 的导出与检查**

- 保留 raw 原始层，转换结果写入独立目录；保存转换参数与源文件校验和，禁止覆盖原始示范。
- 固定 LeRobot 版本，使用该版本支持的 v3 创建/读取 API；不要手写一个外观类似但无法读取的目录。
- 导出相机、observation.state、action、任务文本、episode 边界、FPS 和元信息；详细原始时钟/异常标记可以保留在可追溯的旁路文件。
- 用 CPU 重新打开导出数据，读取每条 episode 的首尾和关键抓取片段；验证双路视频可解码、图像颜色顺序正确、样本数和维度一致、指令和源 episode 一致。
- 检查未来 action 窗口只属于当前 episode；短尾部的有效长度/padding 信息需明确，不能跨到下一条。正式训练时仍须按所选 Wall-X loader 验证 mask 处理。
- 只基于 train 划分计算低维数据分布，报告各维 min/max、分位数、常量维和异常值。区分数据质检统计、LeRobot 元数据统计和 Wall-X 使用的归一化文件。
- 本地执行 CPU 质检与统计；Wall-X 官方归一化统计及训练 loader 核验在 H100 完成，统计仅用 train 划分。未经官方转换核对的本地统计不得宣称为训练已验证的 norm_stats。
- 冻结源 episode、split、schema／转换版本和文件校验和，再传至 H100 的独立数据版本目录；两端核对文件数与哈希，服务器重新读取并形成真实 batch。大文件传输不阻塞采集或控制，原始数据保留。
- 留下 key_mappings 和动作/状态配置草案及未决项；“数据可在 CPU 加载”与“Wall-X 训练 batch 已验证”分别报告。

**9. 历史远程推理与机器人执行设计（已撤销）**

以下是旧的 H100 远程服务／本地执行器设计。当前推理入口面向独立 Ubuntu RTX 5070 Ti 主机，默认监听 localhost；目标部署验证记录为 `NOT_RUN`，尚无目标机实跑验收报告。本轮不连接或驱动机器人，因此本节不是部署入口。旧方案原拟从记录观测的 dry-run 开始，再开展网络与执行器联调。

- 使用 SSH 隧道连接远端服务，携带 session／episode／generation、请求编号、观测时间、模型及动作契约版本。服务器返回动作块，本地验证身份、维度、有限值、物理范围和时效，再按已验证的控制方式下发。
- 网络请求、图像编码、日志和文件传输均不阻塞底层控制。遥操作示范可独立于服务器运行，SO101 接管在本地生效并撤销未执行的模型动作。
- 断连、超时、观测过旧、重复或跨 episode 的响应均不能继续驱动机器人；调用现场验证的暂停／保持／停止流程。重新连接后重新对齐，不重放旧块；不能用零向量代替控制器停止语义。
- 以本地单调时钟记录采集、发送、响应、实际下发与反馈时间；不直接比较两端单调时钟。测量完整链路 p50/p95/p99，并据此配置最大观测 age、响应超时和执行窗口。相机帧率不代表模型调用或机器人闭环频率。
- 保留服务器提案、坐标／单位变换、限幅后最终目标、发送／接受状态和实际反馈。向服务器回传实际执行步数、接管来源、reward／terminated／truncated 和执行后 next_obs；不把 reset 后初始状态写成终止动作的末状态。

本地闭环的进入条件：C0／C1 通过、已训练的目标任务 checkpoint 可加载、H100 动作接口与网络异常 dry-run 通过、控制器失联和接管流程通过、时效阈值与动作窗口明确；由现场人员在固定任务条件下启动。先评估纯 WALL SFT 与联合训练后 WALL，再进入在线 RLT。未执行真机闭环时只报告采集或协议验收结果。
